# 降 AI 规范（唯一权威）

本文件是「降 AI 模块」的规范出处：论文的去 AI 化与个性化表述要求、摘要去模板化要求，以及字符级清理的字符集与门禁语义，全部以本文件为准。主技能 `mathmodel-core` 只保留强制项摘要并指向本文件，避免两处规范漂移。

> **边界**：降 AI 只处理**表述与字符**，不触碰数学模型、数据与结论。任何修改都不得改变题目回答、数值结果与论证结构；去 AI 的目标是「读起来像人写的」，不是把论文改水、改空。个性化 ≠ 口语化、主观化——判据是「只有这篇论文写得出」，来自本题的具体数值、具体判断与具体边界。

## 三道关

| 关 | 处理对象 | 工具 | 门禁 |
|---|---|---|---|
| 表述级·词表 | 模板腔、套话、空泛、伪洞察等**用词与句式** | `code/check_phrasing.py` + 词表 `code/phrasing-blacklist.json` | 命中即退出 1，需改写后复检 |
| 表述级·结构 | 过长被动句、句式重复、过渡密度、段落节奏、结果小数位 | `code/check_style.py`（阈值见 `--list-metrics`） | 命中即退出 1；风险等级「高/极高」不得交付 |
| 字符级 | 零宽字符、bidi 控制、tag 字符、变体选择符等**不可见 Unicode** | `code/strip_invisible.py`（Layer A 字符集） | 最终 PDF 与 Word 清理后复检必须退出 0 |

三关互补：词表级管「用词像不像 AI」，结构级管「句式段落节奏像不像 AI」，字符级管「带不带 AI 生成工具的隐写标记」。

## 一、AI 写作痕迹识别清单

- ❌ 模板腔开头：`随着…的快速发展`、`在当今社会`、`众所周知`（背景章空泛开头）
- ❌ 过渡词滥用：`首先…其次…最后…`、`综上所述`、`值得注意的是`、`总而言之` 高频堆砌
- ❌ 结构过度工整：每段机械「总-分-总」、排比句过度、各问篇幅与深度雷同
- ❌ 泛化升华：`对未来发展具有重要指导意义`、`为…提供了有力支撑` 等无信息量套话
- ❌ 语气单一无详略：所有问题同等对待，缺乏真人写作的侧重与个性
- ❌ 二元对照 / 冒号揭晓：`不是…而是…`、`最关键的一点：…`（网文笔法，非学术表述）
- ❌ 伪洞察与虚假深刻：`很少有人告诉你`、`大家都忽略的是`、`未来已来`、`这只是开始`
- ❌ 权威含糊：`研究表明`、`专家认为` 不给出处（既是 AI 痕迹，也触碰反造假红线）
- ❌ 空泛形容词/程度堆砌：`至关重要`、`极其重要`、`显著提升`（须改为专业表述 + 数值或机制）
- ❌ 冗长连接/铺垫语：`简而言之`、`从某种意义上说`、`不得不说`（删掉后信息量不变）
- ❌ 模板化目的句：`为了更好地…`、`旨在…`、`以期…`（常与后文实际做法重复）
- ❌ 英文 slop（英文摘要/图注）：`delve`、`leverage`、`it's worth noting`、`In conclusion` 等，见 [`no-ai-slop-reference.md`](no-ai-slop-reference.md)

## 二、去 AI 改写规则

1. **章节开头直入主题**：以事实/数据/文献切入，禁 `随着…发展`
2. **过渡句携带信息量**：衔接句含上问结论或下问任务实质，禁纯形式衔接
3. **详略得当**：重点问题详细展开（建模+求解+验证），次要环节从简（一段带过）
4. **结论个性化**：结合本题具体数值与情境，禁通用升华套话
5. **自查流程**：全文依次跑 `check_phrasing.py`（词表级）与 `check_style.py`（结构级），命中即改写，改完复检至双双退出 0
6. **连接词频控**：`首先…其次…再者…最后` 连接链全文至多一组，且仅用于单一求解流程内部的步骤引导；问与问之间一律用信息量句式，每个连接词后必须跟随实质步骤内容

## 三、负面清单

- ❌ 机械分条（（1）（2）（3））行文
- ❌ 无依据空泛词：`很明显`、`显而易见`、`大量`、`效果很好`（须改为具体数值）
- ❌ 含糊收尾：`一定程度上`、`有望`、`大概`（每问必须给出明确结论段）
- ❌ 纯形式衔接：问题间无承上启下，或衔接句不含实质信息
- ❌ AI 痕迹：模板腔开头、套话升华、过渡词滥用、结构过度工整
- ❌ 口语化主观：`我们想`、`我觉得`、`其实`、`搞定了`
- ❌ 结论无因果：只给结果不给「由…可知」
- ❌ 图表孤立：图/表前后无文字过渡
- ❌ 模板腔结果表述：`较为理想`、`具有一定的实际意义`、`具有参考价值`（须改为具体数值与具体场景）

## 四、个性化表述规范

个性化对应评审口径中的「建模的创造性」，须以数据与逻辑为支撑，不等于口语化与主观断言。论文中应写入五处痕迹：

1. **判断痕迹（方法选型处）**：写「本题特征 → 候选比较 → 取舍依据」的判断链，至少提及一种被放弃的替代方案，放弃理由须落在本题规模/约束结构/数据特征上；禁止教科书式算法通史
2. **局限性量化批判（模型评价处）**：禁止「本模型存在一定局限性」式空话；按四步法——点名具体假设 → 指出何种现实情形下失效 → 用敏感性/误差数据量化影响幅度 → 给出适用边界表述（局限须客观非致命）
3. **机理阐释（结果分析处）**：结果出现反直觉或非单调现象时主动设问并给出因果链（「这一现象可归因于：当…时，…，进而…」），禁止只罗列数据
4. **现实案例锚定（结果分析/推广处）**：把结论映射到真实行业实践或公开数据作对照；案例与数据**必须联网核实并标注来源，禁止编造**（反造假红线）；找不到可核实案例则跳过，宁缺毋假
5. **三方向展望（改进与推广处）**：沿数据（引入何种新数据源可放松何种假设）、方法（何种新工具适配本文何种瓶颈、预期难点）、场景（调整何种参数可迁移至何种场景）三个方向给出线索；每条有切入点与预期难点，禁止 `具有重要意义`/`填补空白` 式空泛升华

**边界**：禁用 `我觉得/我们认为大概/肯定最好`；任何「更好/更优」必须附数值与比较基准。

## 五、摘要去模板化

摘要是初评的第一评审现场（单篇阅读约 5-10 分钟，第一轮基本只读摘要）。模板化摘要（套话开头 + 方法空名 + 结果缺位）是最常见的扣分形态。

**模板腔禁用（命中即改写）**：

| 模板腔写法 | 改写方向 |
|---|---|
| `随着…的快速发展，…问题日益受到关注` | 以具体矛盾/关键数字直入 |
| `本文对…问题进行了深入研究` | 目标直述：`针对[核心决策]，本文建立…` |
| `建立了合理的数学模型/采用有效的算法求解` | 点名模型结构、决策变量与算法改进点 |
| `得到了较为理想的结果/结果有所提升` | 具体数值 + 对比百分比 |
| `具有一定的实际意义/具有参考价值` | 指明具体决策场景与迁移空间 |

**关键要求**：每个问题必须给出具体数值结果（精确到小数点后 2-4 位）；必须包含误差/不确定度分析；必须体现问题间的递进关系；开头必须有实质钩子（矛盾/数字/困境），方法名称与正文完全一致。五段式结构与字数预算见主技能「摘要写作模板」及 `mathmodel-paper` 的 `templates/abstract-template.md`。

## 六、结构级规范与十项升级细则

表述级第二关由 `check_style.py` 承担（句子 / 段落 / 数据）；处理不了的条目（逻辑、风格、图表、文献、综合评估）列入人工核对清单。十项要求与落点：

| # | 要求 | 落点 | 类型 |
|---|---|---|---|
| 1 | 词汇：剔除 AI 套词与空泛形容词，改掉模板化书面表达（含英文摘要/图注的英文 slop） | `check_phrasing.py`（19 条规则，含 `en-slop-*`） | 自动 |
| 2 | 句式：拆分 >25 字被动句；同类句式连续 ≤3 次；每段过渡词 ≤2；长短句比例约 1:2 | `check_style.py` M1/M2/M3/M4 | 自动 |
| 3 | 段落：相邻段落字数差异 ≥20%；打破「总-分-总」定式 | `check_style.py` M5 + 人工 | 半自动 |
| 4 | 逻辑：补齐缺失的模型假设与局限；≥2-3 处自审；结论须有数据/理论支撑 | 人工核对清单 | 人工 |
| 5 | 风格：研究判断表述、近似假设说明、不确定性标注 | 人工核对清单 | 人工 |
| 6 | 数据：统一保留 2-4 位小数、关键数据补 ±误差、做灵敏度分析 | `check_style.py` M6 + 人工 | 半自动 |
| 7 | 图表：标题体现结论、坐标轴带物理量与单位、图例可独立理解 | 人工核对清单 | 人工 |
| 8 | 结构：摘要/正文/结论重合度 <30%；结论在摘要基础上深化 | 人工核对清单 | 人工 |
| 9 | 文献：引用与内容对应、格式统一（GB/T 7714-2015）、不堆砌 | 人工核对清单 | 人工 |
| 10 | 综合：通读评估风格一致性，评定风险等级（低/中/高/极高） | `check_style.py --json` 的 `risk` + 人工 | 半自动 |

### 6.1 句式与段落（自动）

`check_style.py` 的六项结构指标与阈值见 `--list-metrics`：过长被动句（>25 字且含被动标记）、句式重复（连续 ≥4 句同一开头）、过渡词密度（每段 >2）、长短句比例（长句占比须落在 20%-50%，目标 1:2）、相邻段落字数差异（≥20%，合格段落 ≥4 段时统计）、小数位（≤4 位）。统计类指标在样本过小时自动跳过；**列表项、表格行与编号分点（`假设 X`、`（1）`、`①`、`步骤 X`、参考文献条目 `[1]`）、清单块的换行续行与 HTML 区块不参与统计**——清单类同形开头是章节格式要求（见 `mathmodel-score` 的 `docs/chapter-checklist.md`），不算句式单调。

**适用范围**：结构级指标面向**论文稿**（`.tex` 与论文类 `.md`）的连续叙述段；项目说明文档（README、规范、SKILL）只过词表级（`check_phrasing.py`），不套用行文节奏类指标——文档的标题层级、折行与表格不是论文行文。

```bash
python3 code/check_style.py paper/paper.tex            # 只报不改，命中即退出 1
python3 code/check_style.py paper/*.tex --json         # 机器可读输出（含 risk）
python3 code/check_style.py --list-metrics             # 查看指标与阈值
```

### 6.2 逻辑、风格、图表、文献（人工核对清单）

- **逻辑严谨性**：主动找出「过于完美」推理链中缺失的假设与局限；全文至少 2-3 处对研究方法的客观自审（点名假设 → 失效情形 → 量化影响 → 适用边界）；所有结论须能指向具体数据、公式或文献
- **研究表述风格**：适度使用带判断的表述（`本研究认为`、`从结果看`）与近似说明（`在…条件下可近似认为`）；不确定结果明确标注范围（`该结论在…范围内成立`），但不得用含糊词替代数据
- **图表系统**：图题直接体现核心结论（而非「XX 图」）；坐标轴写全物理量与单位；图例确保图可独立理解；图表解读文字同样受 `check_phrasing.py` 词表约束
- **全文结构**：摘要 / 正文 / 结论两两对比，重复率 <30%；结论在摘要基础上深化（研究意义、应用前景、未来展望），不是摘要复述
- **参考文献**：逐条核对引用位置与文献内容的相关性；格式统一为 GB/T 7714-2015；不机械堆砌，每篇有明确引用价值

### 6.3 修订痕迹与风险等级（强制）

- **逐段通读 + 保留痕迹**：不得粗略扫读；每处改写保留「原句 → 改句 → 命中规则/依据」三元组，写入 `paper/deai-log.md`（或对话内对照表），确保可追溯、可复核
- **风险等级**：`check_style.py` 按命中密度与高危项数量给出 `低` / `中` / `高` / `极高`（`--json` 的 `risk` 字段）；两检查器合并评估后仍为「高」或「极高」时不得交付，须继续改写并复检

## 七、字符级清理（strip_invisible.py）

字符集与保护逻辑移植自 [guillaumemeyer/watermarks-remover](https://github.com/guillaumemeyer/watermarks-remover) 的 Layer A（`service/scripts/text_unicode.py`）：零宽家族（ZWSP/ZWNJ/ZWJ/WJ/ZWNBSP）、bidi 与格式控制、tag 字符（U+E0001–U+E007F）、变体选择符、非字符、保留不可见字符与私用区。默认对中文/拉丁学术文本全部剥离，仅保留 CJK 表意文字后的 IVD（变体选择符 U+FE00–U+FE0F / U+E0100+）作为合法正字保护。

支持格式与清理范围：

- `.docx`：zip 内**正文相关 part**（document/footnotes/endnotes/comments/header/footer、docProps）的文本节点与数字字符引用实体；`fontTable.xml`/`styles.xml` 等含合法 PUA 符号字体的 part 一律不碰，避免误伤
- `.pdf`：ToUnicode 映射定位隐形码 → 内容流 hex 清理 + 元数据清理（需 PyMuPDF）
- `.tex` / `.bib` / `.md` / `.txt` 等：文本级清理（含文件头 BOM）

```bash
python3 code/strip_invisible.py FILE...                    # 只检测，发现即退出 1
python3 code/strip_invisible.py --clean FILE...            # 就地清理（默认留 .bak），清理后复检
python3 code/strip_invisible.py --clean --no-backup FILE...
```

退出码：`0` 全部干净；`1` 存在（或清理后残留）不可见字符；`2` 用法/依赖错误。PDF 模式需 `pip install pymupdf`；tex/docx 模式仅用标准库。

**交付门禁（强制）**：编译前先清理 `.tex` 源（从源头杜绝），**最终 PDF 与 Word 都必须清理并复检**；复检若仍报 `CLEANED-RESIDUAL` 不得交付，回查 tex 源与转换链。命令见 `mathmodel-paper/SKILL.md` 快速流程。

## 八、两道表述级检查器（自动门禁）

表述级共两道：`check_phrasing.py`（词表级，规则为数据）与 `check_style.py`（结构级，阈值见 `--list-metrics`）。二者协同：词表抓词汇与句式痕迹，结构抓句长 / 句式重复 / 过渡密度 / 段落节奏 / 小数位。

规则表是数据：词表写在 `code/phrasing-blacklist.json`，**加词只改它**，检查器与文档同步生效。

```bash
python3 code/check_phrasing.py paper/paper.tex          # 只报不改，命中即退出 1
python3 code/check_phrasing.py paper/*.tex --json        # 机器可读输出
python3 code/check_phrasing.py --list-rules              # 查看词表与规则
```

- **频次上限**：带 `max_per_document` 的规则是频次上限，**超出部分才算命中**——例如全文用一次「综上所述」可接受，堆砌则会被报出
- **跳过范围**：围栏代码块与行内代码跨度（反引号包裹），故本文件里写成行内代码的反例不会被误报，检查器可直接扫本技能文档做自检
- **退出码**：`0` 通过 / `1` 有命中 / `2` 用法或环境错误（与 `strip_invisible.py`、`validate_*.py` 语义一致）
- **扩词流程**：在 `phrasing-blacklist.json` 的 `rules` 中新增一条（`id`/`label`/`severity`/`why`/`fix`/`patterns`/`max_per_document`），正则为 Python `re` 语法；本文件对应补一行说明。示例正反例见 `examples/clean-sample.tex` 与 `examples/slop-sample.tex`
- **结构级示例**：`examples/style-slop-sample.tex` 供 `check_style.py` 冒烟（应命中六项指标）；`examples/clean-sample.tex` 为正例（两检查器都应零命中）。结构级指标阈值写在脚本头部常量，调整阈值即调 CI 与文档口径，故改动需同步本文件 6.1
- **英文规则**：词表含 `en-slop-word` / `en-slop-phrase` / `en-slop-pattern`，面向英文摘要与图注（英文期刊、国外赛事的摘要与图注），模式清单与来源见 [`no-ai-slop-reference.md`](no-ai-slop-reference.md)；冒烟样本 `examples/slop-sample-en.md`（应命中）与 `examples/clean-sample-en.md`（应零命中）
