# 方法选型指南

方法清单见 [method-library.md](method-library.md)，实现入口见 [implementation-guide.md](implementation-guide.md)。
本文件给出选型流程、判断依据与常见误用，**最终选型由使用者确认**。

## 一、选型流程

1. **问题定性**：判断子问题属于哪个问题族（优化 / 预测 / 评价 / 分类 / 微分方程 / 仿真 / 信号），
   依据是数据结构、约束条件与要回答的结论；不按题目章节顺序套方法。
2. **取候选**：每个子问题取 2–3 个可行方法，其中至少 1 个具备明显创新性（改进算子 / 混合策略 /
   交叉学科方法）。候选来源于 [method-library.md](method-library.md) 的问题族索引。
3. **出候选对比表**：见下方模板，逐项如实评估，标注**推荐项与一句推荐理由**。
4. **交使用者选择**：等待确认或改选；明确委托代选时按推荐项执行。

## 二、候选对比表模板

| 候选算法 | 核心思路 | 创新度 | 可解释性 | 实现难度 | 预计耗时 | 精度 / 鲁棒性预期 |
|---|---|---|---|---|---|---|
| 例：熵权-TOPSIS | 熵权定客观权重，TOPSIS 按贴近度排序 | 中 | 高 | 低 | 分钟级 | 中，对指标权重敏感 |

- 评级用「高 / 中 / 低」；耗时按数据规模给量级（秒级 / 分钟级 / 小时级）；
- 评估须基于本题的数据规模与约束，禁止夸大创新度或低估实现难度；
- 表中须标注推荐项与推荐理由，避免只列不选。

## 三、问题特征 → 推荐方法

| 问题特征 | 推荐方法 |
|---|---|
| 非线性、不连续或不可导 | 遗传算法 |
| 0-1 变量 | 0-1 整数规划 + 遗传算法 |
| 高维决策空间 | 分层构建初始解 + 智能优化 |
| 多方法融合 | 多模型加权集成、分阶段混合求解（启发式 + 精确校正） |
| 评价 / 排序类 | 熵权-TOPSIS（首选）、AHP、灰色关联分析 |
| 指标权重确定 | 熵权法、CRITIC、AHP |
| 最短路径 / 网络流 | Dijkstra/Floyd、最大流、最小生成树 |
| 路径规划 / 配送 | TSP / VRP + GA / 蚁群求解 |
| 时序预测 | ARIMA、Prophet、LSTM；小样本用 GM(1,1) |
| 机理演化类（A 题） | 微分方程组 + RK4 数值解 + 敏感性分析 |
| 方程求根 / 非线性求解 | 二分法、牛顿迭代法 |
| 插值 / 数据补全 | 三次样条插值、拉格朗日插值 |
| 项目排程 / 关键路径 | 关键路径法（CPM/PERT） |
| 连续参数快速优化 | 梯度下降、共轭梯度（大空间改用智能优化） |

## 四、选型原则（强制）

1. **拟合性优先于高级性**：先看与问题结构、数据规模、约束条件是否匹配（可求解、可靠、可解释），
   再谈创新；禁止为炫技强行引入与问题不适配的高深算法，导致求解困难或结论不可信。
2. **方法梯度**：能用初等方法解决的不用高等方法，能用简单方法解决的不用复杂方法，
   能用被更多人看懂的方法不用只有少数人看懂的方法。
3. **创新落点明确**：创新可落在建模（模型本身、简化策略）、求解（解法与算子改进）、
   结果（表示 / 分析 / 检验方式）、推广（应用与迁移）四处中的一处；创新须回答
   「解决了旧方法解决不了的什么问题」，而不是堆砌新名词。
4. **验证手段与问题类型匹配**：方法选定后，验证方式随之确定（见第五节），
   不套用固定流程、不为有验证而验证。

## 五、按问题类型的验证方式

| 问题类型 | 验证方式 |
|---|---|
| 优化类 | 迭代收敛曲线 + 替代算法（或精确法）互验 + 参数敏感性；能报告 optimality gap 更好 |
| 多目标 | 以 ε-约束法或全域扫描获取全域 Pareto 前沿，说明折中方案选取依据；禁止只靠人为给定权重集 |
| 预测类 | 留出法 / 时序交叉验证，报告 MAE / RMSE / R²（按需补领域指标）与分组 / 分时段误差拆解；预测注入下游决策时分析误差传导 |
| 评价类 | 权重扰动鲁棒性检验 + 与替代评价方法对比 |
| 微分方程类 | 与解析解 / 极限情形对比 + 守恒量校验 + 步长收敛性验证 |
| 通用 | 稳健性 / 敏感性检验，扰动对象与问题类型匹配；无不确定参数的模型不做形式化扰动 |

## 六、问题递进关系

| 递进类型 | 典型表述 |
|---|---|
| 简单 → 复杂 | 「在问题一的基础上，进一步综合考虑……」 |
| 静态 → 动态 | 「考虑到实际因素 / 动态变化……」 |
| 确定 → 不确定 | 「在确定的最优配置基础上，引入随机需求（不确定性），构建随机规划模型」 |
| 单目标 → 多目标 | 「引入多目标优化，采用 NSGA-II 求解 Pareto 前沿……」 |

问与问之间的方法递进要在论文里显式命名（如「静态基线 → 约束扩展 → 动态鲁棒」），
并说明前问结果为后问提供了什么（基准 / 参数 / 输入）。

## 七、常见误用

| 误用 | 后果 | 纠正 |
|---|---|---|
| 为高级而高级：与问题结构不适配的深度模型 | 求解困难、结论不可信 | 回到拟合性优先，先保证可求解与可解释 |
| 只给方法名不给结构 | 模型不完整、无法复核 | 至少给出目标函数、决策变量与约束的完整数学结构 |
| 多目标只用人为权重集 | 得到的不是全域 Pareto 前沿，折中依据不足 | 用 ε-约束法或等价全域扫描获取前沿，再说明选取依据 |
| 通用模板式算法介绍 | 与本题脱节，像换个题目也能用 | 结合本题结构、数据特点与关键超参选取依据撰写 |
| 验证方式与问题类型错配 | 验证不构成证据 | 按第五节对照表选择验证手段 |
| 综合评价值不做标准化方向说明 | 负向指标方向反了，排序错误 | 明确正 / 负向指标的正向化处理与权重来源 |
